# The Studio: a Mac editor with a local preview

20 November 2026. Harry was not happy with the browser editor at `/edit/`: installed as an app it has no browser navigation, and its preview lives inside the editing screen. He asked for an editor that runs the site on a local web server, reloads it on every change, publishes with one button, shows a history, and takes events, albums, menu and pictures.

## What we chose

| Question | Choice | Why |
|---|---|---|
| Whose Mac | Harry's first, Elias's later (Harry) | The app needs bun, git and a copy of the site; packing that for a Mac without developer tools is a later step |
| The phone editor at `/edit/` | Stays | Small changes on the go |
| Publish | A pull request on an `edit/...` branch. For the owner it waits for the `build` check and merges itself; for anyone else it stops and waits for a yes (Harry) | The owner's click on Publish is the approval. Nobody pushes to `main` |
| Alt text | A draft from Apple Vision's labels and read words, finished by hand (Harry) | No key, no download, nothing leaves the Mac. The draft is a list, not a sentence |
| The cut of a picture | A focus point per photo in `focus.yml` | One file per photo stays the rule; the build cuts each shape around the point |
| An Eventfrog import | Becomes an ordinary event file with its source address | The build needs no key and does not depend on Eventfrog being up |
| Keys | macOS Keychain, service `robins-studio` | Not in a file that could be committed or backed up in the clear |
| The window | A small Swift program around a web view; the preview opens in the default browser | Harry wants real browser navigation for the preview |

## How the local server is kept shut

- It listens on 127.0.0.1 only.
- The editing screen is served from `127.0.0.1:<port>`, the preview from `localhost:<port>`. To a browser these are two origins, so a page of the built site cannot call the editing API.
- Every API request needs a token made new at each start, and the server's own Host and Origin.
- A write names no path of its own: the server builds it from a checked short name under a fixed folder, inside the edit scope.

## Known limits

- Not checked against GitHub yet: the owner's self merge through the API under the rule that asks for one approval. The first real publish will show it; if GitHub refuses, the screen says so and links the pull request.
- The Eventfrog list with a key is tested only against a made-up answer. Its shape is taken from the comedy site's client. The bar has no key yet.
- Neither poster for beer pong or chess prints a time, so those events show the day only.
- The app is not signed and has no icon. On another Mac, Gatekeeper will ask.
- A person who is not the owner stays on the `edit/...` branch after sending; nothing brings the folder back to `main` when someone else merges.
- The branch is cut from the folder's state. If `main` moved on GitHub in the same file, the merge is refused and nothing is rebased.
- The Studio works on the folder it is started from. Use a clone kept on `main`, not the folder where code is written.
