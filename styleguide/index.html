Design system

Style guide

Every token and component the site is built from. Use the cup and cocktail switch in the header, or add ?theme=day or ?theme=night to the address, to see either theme.

The rule: a value that more than one thing shares is a token in site/data/tokens.json (colour, type, space, radius, border, shadow, motion, layers, tap targets, measures, breakpoints). The geometry of one component (a thumbnail width, a column count, a tilt) stays in the stylesheet next to that component. A test enforces both halves.

drink-card: d (a drink view: name, text, img, alt, url). components/event-promo

event-promo: e (an event view), t, events_url, when (optional: the label, for a fixed example such as the style guide's). The hero's "Tonight", "Today" or "Tomorrow" sign for one event: label, name, time and the way in (tickets, or the pill that says people can just come), plus "and N more" for a busy day. The build writes one per event of the next days, hidden; site.js shows the one the Zürich clock picks and fills in the label and the count (when.js). Without JavaScript none shows, so a page never says "tonight" about the wrong night.

On the home page it sits on the hero photo; here it is shown on the same dark ground, once with each label the clock can give.

components/moment-card

moment-card: m (a moment with img, alt, caption, date_label), t. The photo is a plain link to its largest JPEG; with JavaScript, site.js opens it in the lightbox instead (data-lightbox), sized from data-srcset.

components/moments-grid

moments-grid: moments (list of moment views), t, count (optional: show only the first so many). Columns that keep each photo's own shape. One grid is one lightbox group: previous and next stay inside it.

Select a photo: the lightbox opens it large in a native dialog built by site.js, night-coloured, with caption and date. Arrow keys and a swipe step inside one grid; Esc or the close button closes and focus returns to the photo. Without JavaScript the link opens the JPEG.

components/nav-icon

nav-icon: name ('events', 'moments', 'menu' or 'coffee'). A small badge in the manner of the ROBIN's roundel: a ring, a dotted inner ring like the logo's ornament, and a line drawing in the middle: a calendar for what's on, an eye for the moments, a cocktail glass for the menu (and the night side of the theme switch), a coffee cup for the day side. Drawn in currentColor, so it follows the text colour and the theme; decorative (aria-hidden), the link carries the words.

The header's three places, and the coffee cup and cocktail of the theme switch. On a phone the pill shows the icon only; the words stay for screen readers.

components/open-pill

Live from hours.yml and the Zürich clock; hidden without JavaScript.

components/photo-strip

Layouts

LayoutWhat it is
layouts/basebase: the frame of every page: head (meta, link preview, favicons, theme script), header, main, footer, the one script. Every other layout fills its `content` block.
layouts/drinkdrink: one drink of the menu on a page of its own, made by the build for every drink a season names (/menu/<slug>/). Dressed like the bar's menu cards: the drawing whole on its dark, cream and red, a double frame. Name, season, the short line (no price: in Switzerland a price is kept quiet), then only the parts that exist: what it is like, what goes in, how to make it, photos (the gallery lightbox), the seasons it was on the menu. Recipe data only when there are ingredients.
layouts/eventsevents: the events of the next 60 days, grouped by month, with the calendar link. With JavaScript, site.js moves the events of today and the next six days (Zürich time) into "This week" at the top, so none is listed twice and an emptied month heading goes; without it the page is the plain month list.
layouts/gallerygallery: every moment, albums first, each grid one lightbox group.
layouts/homehome: the sections named in home.yml. The page is written in the night order (`sections`), which is also what a visitor without JavaScript gets; by day the script below puts them in the `sections_day` order before the page is first drawn, and again whenever the theme switch is used. It moves the DOM itself, so reading and tab order follow what is seen. A list marked data-arrange (the guest cards) is put in its data-day order the same way.
layouts/menumenu: the cocktail menu, season by season: the season shown today first with its drinks, then the seasons to come and those that are over.
layouts/movedmoved: the note at /edit/, where the retired phone editor lived. It says in English and German that the editor is now ROBIN's Studio, links to the install page, and removes the key, the draft and the worker the old editor left on the phone. noindex.
layouts/notfoundnotfound: the 404 page. It is shown at any address, so it cannot know the visitor's language: every language gets its block, and site.js moves the right one to the top when the address says which.
layouts/pagepage: a plain text page from a Markdown file: title and prose.
layouts/styleguidestyleguide: this page. Tokens are listed straight from tokens.json, so a new token shows up by itself. Components and sections are listed from the template folders with the comment each file starts with; a new one needs its example added in the `case` below (a test fails while it is missing). This page is internal: English only, noindex.

sections/ticker

ticker: t. Two identical groups in one track that slides left by half its width, so the loop has no seam. The words are decoration (the address is in "Find us"), so they are hidden from screen readers. The whole ticker is one button without a visible mark: a tap, a click or Enter pauses the movement and starts it again (WCAG 2.2.2). It runs from the start on every device, also with "reduce motion" on (Harry's decision, 16 Nov 2026).
